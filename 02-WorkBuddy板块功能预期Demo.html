实现路线

上面 Demo 里标的 已实现 / 规划 对应下面各阶段。

P0已完成

协议层对齐

统一三段式 UA、X-Auth-Refresh-Source: plugin、归因头组、国际积分路径与 CN 双路目录、parseV3Catalog 非对话模型过滤。仅改 src/upstream.ts。

已验证 341/2 基线4 项国际/企业路径待活测
P1下一步

独立设置板块骨架

新增 WorkBuddySettingsSection.tsx，注册 settings.section（id:'workbuddy'、order:25）；四页标签状态自持；现有两张卡片保留为 Plugins 区概览入口。

无需加依赖需同步改 client-fallback.spec.ts
P2

展示补齐（建议前置）

积分实时/缓存标注 + 套餐到期倒计时；模型中心可排序表格（倍率/档位/上下文/能力）+ 别名映射；i18n 扩语言。否则 P1 的板块是空壳。

P3

远程池模式

把上游 base 参数化，让 DSH 直连 workbuddy2api 网关。红线：本地 auth token 与 remote key 不得同现于一个请求。

P4

用量埋点

shim 记录 per-request 指标到 jsonl（注意增长与轮转），用量页按模型与按日聚合。

P5

同源测试台

复用 probe 的 loopback + 每进程随机密钥模式，加受控试调路由与组件。

P6

可选多账号（高风险）

移植账号池选号/冷却策略，并一并补 X-Machine-ID/X-Session-ID。禁止按时间戳挑 token；X-User-Id 必须与实际账号严格绑定；需默认关闭的显式授权开关。
